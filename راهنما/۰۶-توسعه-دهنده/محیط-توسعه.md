# محیط توسعه

---

## ۱) پیش‌نیازها

| ابزار | نسخه | توضیح |
|---|---|---|
| Node.js | ≥ ۲۰.۱۱ (ترجیحاً ۲۲ LTS) | `engines` در `package.json` |
| npm | ≥ ۱۰ | همراه Node |
| MySQL | ۸ یا MariaDB 10.4+ | یا از SQLite استفاده کنید |
| (اختیاری) Docker | — | برای اجرای سریع MySQL |

---

## ۲) راه‌اندازی

```bash
git clone <repo> azmoonak
cd azmoonak
npm install

cp .env.example .env       # ویندوز: copy .env.example .env
```

سپس در `.env`:

```ini
DB_MODE=sqlite             # برای توسعه سریع بدون MySQL
# یا
DB_MODE=mysql
MYSQL_URL=mysql://root:root@127.0.0.1:3306/azmoonak
SESSION_SECRET=dev-secret-local-only
AI_PROVIDER=none           # یا anthropic + کلید واقعی
```

MySQL آماده با Docker:

```bash
docker compose up -d        # MySQL 8.4 روی پورت 3306 با کاربر root/root
```

## ۳) اجرا

```bash
npm run dev          # سرور (tsx watch) روی پورت 4000
npm run dev:web      # رابط کاربری (Vite) روی پورت 5173
```

در حالت توسعه، رابط کاربری روی `5173` بالا می‌آید و درخواست‌های `/api` را به `4000` پروکسی
می‌کند. برای تست API مستقیم، `http://localhost:4000` را صدا بزنید.

## ۴) تست‌ها

### تست API سرتاسری
```bash
# سرور را بالا بیاورید، بعد:
npm run test:api
# یا با BASE دلخواه:
BASE=http://127.0.0.1:4000 npx tsx server/scripts/smoke-test.ts
```

این تست: سلامت سرویس → ورود مدیر → فهرست آزمون‌ها → داشبورد → resolve کد → شروع تلاش →
دریافت سوال → ذخیره پاسخ → ثبت نهایی → تحلیل → خروجی CSV → وضعیت AI را بررسی می‌کند.

### بررسی SQL بدون نیاز به MySQL
```bash
npm run check:sql
```
DDL و کوئری‌های aggregate را با dialect مربوط به MySQL تولید و بررسی می‌کند (با یک pool
شبیه‌سازی‌شده) — برای اطمینان از اینکه کوئری‌ها روی MySQL هم درست کار می‌کنند.

### بررسی تایپ
```bash
npm run typecheck
```

## ۵) سبک کدنویسی در این پروژه

| قاعده | دلیل |
|---|---|
| تایپ‌های مشترک در `packages/shared` | سرور و رابط همیشه هم‌نسخه باشند |
| اعتبارسنجی با Zod در مرز API | ورودی نامعتبر هرگز به لایه‌ی سرویس نمی‌رسد |
| خطا با `throw badRequest(...)` و غیره | پیام فارسی + کد HTTP از یک نقطه |
| کوئری فقط در `db/repos.ts` | سرویس‌ها مستقل از SQL بمانند |
| نمره ×۱۰۰ | پرهیز از خطای اعشار |
| `*.partial()` فقط روی شکل بدون `.default()` | جلوگیری از ریست شدن فیلدها در ویرایش جزئی (درس Zod v4) |

## ۶) افزودن قابلیت جدید — مسیر پیشنهادی

۱. **قرارداد مشترک**: اگر داده‌ای بین سرور و رابط جابه‌جا می‌شود، نوع DTO و (در صورت نیاز)
   اسکیمای Zod را در `packages/shared/src` اضافه کنید.
۲. **دیتابیس**: اگر ستون/جدول جدید لازم است، یک migration جدید در `server/src/db/migrations.ts`
   اضافه کنید (شماره‌ی بعدی + نام یکتا). هرگز migration قبلی را تغییر ندهید.
۳. **لایه داده**: توابع repository را در `server/src/db/repos.ts` اضافه کنید.
۴. **منطق**: یک سرویس در `server/src/services/` بنویسید (بدون دست‌زدن به HTTP).
۵. **API**: مسیر را در `server/src/routes/` اضافه کنید و در `routes/index.ts` وصل کنید.
۶. **رابط**: صفحه/کامپوننت در `web/src/` بسازید و در `App.tsx` مسیر بدهید.
۷. **تست**: با `npm run test:api` یا یک تست دستی مطمئن شوید.

## ۷) ساخت بسته‌ی تحویلی

```bash
npm run release
```

- خروجی: `release/azmoonak-v1.0.0.zip`
- فایل‌های `.env`، `data/`، `dist/`، `node_modules/` و پوشه‌ی `release/` **داخل بسته نمی‌روند**.
- نام فایل‌های فارسی در بسته به معادل ASCII تبدیل می‌شوند (مثلاً `QUICKSTART-FA.md`) تا روی
  ویندوزهای قدیمی مشکل ایجاد نشود.
